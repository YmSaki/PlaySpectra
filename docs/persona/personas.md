# ペルソナとユースケース

## 1. AIエージェント開発者 (AI Agent Developer)
**概要:**
LLMを用いた自律型AIエージェントを開発しており、エージェントがVRアプリケーションの世界を理解し、自律的に操作できるようにしたいと考えている。

**主なユースケース:**
* **状態の観察:** `vr_screenshot` を用いて現在の画面をキャプチャし、VLM (Vision-Language Model) で画面内のオブジェクトやUIを認識する。
* **空間の理解:** `vr_view` を用いて、画面上のピクセル座標とVR空間の3D座標のマッピングを行い、オブジェクトの正確な位置を把握する。
* **自律的な行動:** `vr_look_at` で注目したいオブジェクトに視点を向け、`vr_input` や `vr_click` を用いてオブジェクトを掴んだり、ボタンを押したりする。
* **アクションの探索:** `vr_actions` を実行して、そのVRアプリがどのような操作（Grab, Teleportなど）を受け付けるかを動的に発見し、行動計画を立てる。

**期待するシステムの振る舞い:**
* 不正なパラメータを送信してもクラッシュせず、有用なエラーメッセージ（JSON）が返ってくること。
* AIの推論ループに組み込みやすいよう、すべてのツールが安定して動作し、状態が予測可能であること。

## 2. QA自動化エンジニア (QA Automation Engineer)
**概要:**
VRアプリケーションの品質保証を担当しており、継続的インテグレーション(CI)パイプラインで自動化されたE2Eテストを実行したいと考えている。

**主なユースケース:**
* **リグレッションテスト:** 特定の入力シーケンス（例：歩行してアイテムを拾う）を `vr_input` と `vr_wait` で正確に再現し、予期せぬ挙動がないか確認する。
* **アサーションのためのキャプチャ:** 操作後の状態が正しいかを検証するために、`vr_screenshot` を取得し、画像比較によるテストを行う。
* **インタラクションの確認:** オブジェクトを正しく掴めたかを確認するために、`vr_haptics` を監視して、アプリケーションから正しい振動フィードバックが返ってきているかをアサートする。

**期待するシステムの振る舞い:**
* ヘッドレス環境（Meta XR Simulatorなど）で完全に動作し、実機のHMDを必要としないこと。
* テストスクリプトが安定して動作するよう、フレームの同期（`vr_wait`）や入力の確実な反映が保証されていること。

## 3. VRアプリ開発者 (VR Developer)
**概要:**
自社エンジンやUnity/UnrealなどでVRアプリを開発しており、ビルドしたアプリの挙動を手軽にデバッグ・検証したいと考えている。

**主なユースケース:**
* **特定ハードウェアのモック:** 開発環境に実機コントローラーがなくても、`vr_set_controller` で任意の位置に仮想コントローラーを配置し、UIの動作確認を行う。
* **グラフィックスAPIの検証:** VulkanやD3D11/D3D12など、複数のグラフィックスAPIでのレンダリング結果の違いを、`vr_screenshot` を使って素早く比較する。

**期待するシステムの振る舞い:**
* 対象のVRアプリのソースコードやエンジンに変更を加えることなく（OpenXR APIレイヤーとして）、透過的に注入できること。
* エンジン非依存であり、どのエンジンで作られたアプリでも等しく機能すること。
